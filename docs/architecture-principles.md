# Архитектурные принципы проекта

## Язык документации и код-стиль

- Документация, комментарии и docstrings пишутся на русском языке.
- Функции, методы и конструкторы получают type hints для параметров и возвращаемых значений.
- Публичные классы, функции и методы получают docstrings в формате, принятом в проекте.
- Имена модулей, классов, функций и переменных остаются на английском языке, чтобы код соответствовал стандартам Python.
- Сложная логика сопровождается короткими комментариями о причине решения, а не пересказом кода.

## Чистая архитектура

Зависимости направлены от внешних слоёв к внутренним:

```text
API / Worker / CLI
        ↓
Сценарии приложения и агенты
        ↓
Доменные модели и интерфейсы
        ↓
Инфраструктура: БД, Qdrant, LLM, Redis, HTTP
```

Правила:

- доменная логика не импортирует FastAPI, SQLAlchemy, Qdrant или конкретного LLM-провайдера;
- внешние сервисы подключаются через интерфейсы и адаптеры;
- конфигурация создаётся в `backend/core/config.py` и передаётся в зависимости явно;
- HTTP-маршруты отвечают только за валидацию запроса, вызов сценария и формирование ответа;
- доступ к базе данных и внешним API не размещается в маршрутах или агентах;
- каждый модуль должен иметь одну понятную ответственность.

## SOLID

### Single Responsibility Principle

Один класс или модуль решает одну задачу. Например, поиск документов, генерация ответа и проверка ответа — разные компоненты.

### Open/Closed Principle

Новые LLM-провайдеры и способы поиска добавляются через новые адаптеры, без переписывания сценариев приложения.

### Liskov Substitution Principle

Любая реализация общего интерфейса, например `LLMClient` или `Retriever`, должна быть взаимозаменяемой с другими реализациями.

### Interface Segregation Principle

Интерфейсы должны быть небольшими: клиент генерации не обязан знать о работе с базой данных, а репозиторий документов — о HTTP.

### Dependency Inversion Principle

Сценарии зависят от абстракций, а не от конкретных библиотек. Конкретные реализации передаются через конструктор или фабрику.

## Практическая проверка перед завершением этапа

- [ ] У публичных функций и методов есть type hints.
- [ ] У публичных классов и функций есть русские docstrings.
- [ ] HTTP-слой не содержит бизнес-логику.
- [ ] Конкретные внешние сервисы не протекают в доменные модели.
- [ ] Компоненты можно заменить через интерфейс и протестировать отдельно.
- [ ] Для нового решения добавлен тест или объяснение причины отсутствия теста.
